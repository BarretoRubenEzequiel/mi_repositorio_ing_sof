Qué es Git

Git es un sistema de control de versiones: guarda el historial de cambios de tu proyecto para que puedas volver atrás, ver quién cambió qué y trabajar en equipo sin pisarte los archivos.

No hay que confundirlo con GitHub. Git es la herramienta que corre en tu compu; GitHub es un sitio web donde subís tus repositorios para respaldarlos y compartirlos (existen alternativas como GitLab o Bitbucket).

Repositorio
La carpeta de tu proyecto junto con todo su historial de cambios.
Commit
Una "foto" del proyecto en un momento dado, con un mensaje que explica qué cambió.
Rama (branch)
Una línea de trabajo paralela, para probar cosas sin romper lo que ya funciona.
Remoto
Una copia del repositorio alojada en otro lugar, por ejemplo GitHub.

Instalar y crear tu usuario

Descargá Git desde git-scm.com e instalalo. Para comprobar que quedó bien, abrí una terminal (o Git Bash en Windows) y ejecutá:

git --version

Lo primero que tenés que hacer es decirle a Git quién sos. Ese nombre y ese email van a quedar registrados en cada commit que hagas:

git config --global user.name "Tu Nombre"
git config --global user.email "tuemail@ejemplo.com"

Para revisar la configuración:

git config --list

Si vas a usar GitHub, creá también tu cuenta en github.com y usá el mismo email que configuraste acá, así tus commits quedan asociados a tu perfil.

Crear un repositorio

Hay dos caminos: empezar uno nuevo o copiar uno que ya existe.

Empezar uno nuevo

Entrá a la carpeta de tu proyecto y ejecutá:

mkdir mi-proyecto
cd mi-proyecto
git init

git init crea una carpeta oculta llamada .git donde Git guarda todo el historial. Nunca la borres ni la edites a mano.

Copiar uno existente

git clone https://github.com/usuario/repositorio.git

Los tres estados

Antes de guardar un cambio, pasa por tres lugares. Entender esto resuelve la mitad de las dudas con Git.

Directorio de trabajoTus archivos, con los cambios que hiciste.
git add
Staging (área de preparación)Los cambios que elegiste para el próximo commit.
git commit
RepositorioLos cambios ya guardados en el historial.

Tu primer commit

Creá un archivo cualquiera y seguí estos pasos:

echo "# Mi proyecto" > README.md

git status            # qué cambió y qué está sin seguimiento
git add README.md     # lo pasa al staging
git commit -m "Agrego el README"

Para agregar todos los cambios juntos usá git add .. Escribí mensajes cortos que expliquen qué hiciste, por ejemplo "Corrijo el login" y no "cambios".

Ignorar archivos

Si hay archivos que no querés versionar (contraseñas, carpetas de dependencias como node_modules), creá un archivo .gitignore y listalos ahí, uno por línea.

Ver el historial

git log                 # historial completo
git log --oneline       # una línea por commit
git diff                # cambios que todavía no agregaste
git restore archivo.txt # descarta los cambios de un archivo

git restore borra los cambios sin guardar de ese archivo y no se pueden recuperar. Usalo con cuidado.

Ramas

La rama principal se suele llamar main. Para trabajar en algo nuevo sin tocarla, creás otra rama:

git branch                  # lista las ramas
git switch -c nueva-funcion # crea una rama y te mueve a ella
git switch main             # volvés a main
git merge nueva-funcion     # unís la rama nueva a main

Si dos ramas cambiaron la misma parte de un archivo, Git te avisa con un conflicto. Abrí el archivo, elegí qué versión queda, hacé git add y terminá con un git commit.

GitHub y repos remotos

Para subir tu proyecto, primero creá un repositorio vacío en GitHub (botón New) y después conectalo con el tuyo local:

git remote add origin https://github.com/usuario/repositorio.git
git branch -M main
git push -u origin main

Desde ese momento, el ciclo de trabajo es este:

git pull      # traés los cambios que hay en el remoto
# ...trabajás, git add, git commit...
git push      # subís tus commits

GitHub ya no acepta la contraseña de tu cuenta al hacer push por HTTPS: necesitás un Personal Access Token o una clave SSH. Se configuran desde los ajustes de tu cuenta.
